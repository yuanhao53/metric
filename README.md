# metric-ICLR27

固定二元列表上的指标迁移实验。CPU / NumPy 实现，不依赖 GPU 或 PyTorch。

## 开始使用

在本文件所在目录打开 PowerShell。当前电脑已经配置好 `.venv`，直接运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe run.py all --config configs/smoke.json
```

也可以运行 `run-smoke.ps1`。首次真实数据实验自动下载 MovieLens 1M（GroupLens 官方来源），保留原始压缩包、README、下载地址与 SHA256。迁移到其他电脑时先运行 `setup.ps1 -Python <Python路径>`，建议 Python 3.11 或 3.12。

## 正式实验

```powershell
# 理论核验、尺度与受控动态，不需要下载数据
.\.venv\Scripts\python.exe run.py core --config configs/paper.json
# 完整 MovieLens 数据，BCE/BPR，各三个种子
.\.venv\Scripts\python.exe run.py train --config configs/paper.json
```

也支持 `enumerate`、`scaling`、`dynamics` 单独运行。输出自动归档到 `results/时间-命令/`，包含配置、代码哈希、环境、原始 CSV、汇总 JSON 和 PNG/PDF 图。`--out 路径` 可指定输出目录，但不会覆盖非空实验目录。失败会记录 `error.txt` 和失败状态。

`smoke.json` 仅用于端到端验证：200 个用户、一个种子、3 个 epoch，不能替代正式结果。`paper.json` 是正式实验的起始配置，不是已经调优的设置；BCE/BPR 使用相同模型容量、初始化和训练预算，不预设哪类损失更好。增加调参时应给两者相同预算并仅使用验证集。

## 实验与论文的对应

| 模块 | 验证的问题 | 主要输出 |
|---|---|---|
| enumerate | 所有二元排列的最大 regret 比、可迁移条件、达到边界的排列 | constants.csv、cross_cutoffs.csv、精确阶梯迁移函数与线性包络 |
| scaling | 固定比例/固定正例数下两个全局常数，以及局部交换与全局尺度分离 | scaling.csv、normalized_scaling.csv、尺度图 |
| dynamics | 有利交换、混合前缀变化、独立 logits BCE 与共享参数耦合 | structural_updates.csv 等原始表、优化轨迹及显式反例 |
| train | 真实训练中位置分布与指标冲突，以及验证指标选择的影响 | 逐用户变化、checkpoint 分数、选择结果和训练曲线 |

精确枚举按正例位置组合进行，不重复枚举相同标签排列。正式配置枚举至 n=14，跨 cutoff 枚举至 n=10。已知紧常数核验数值与达到边界的 witness；仅证明有限性的组合只核验有限性，不把粗界称为紧常数。k=n 时 Precision/Recall 为常量，作为目标的最小系数是零。

受控优化使用等权求和 BCE 和显式步长。独立 logits 与可逆线性重参数化的共享模型具有相同表达能力，区别在于梯度耦合；还保存一个损失下降而正确概率排序被破坏的确定性反例。真实模型使用 Adam，不能套用连续梯度流单调性保证。

## 真实数据协议

* 每位用户按时间进行 70%/15%/15% 训练/验证/测试划分；相同时间按物品编号排序。这不是全局时间切分。
* 评分 >=4 为正例，较低的已观测评分为负例；不把未评分物品默认当作负例。评估范围是留出的已评分物品，不代表完整物品库上的无偏偏好评估。
* 验证与测试均具有至少 10 个候选、至少一个正例和负例的共同用户参与评估；保留多个正例，不使用 leave-one-out 作为冲突实验。
* 同一用户的候选和标签在所有 checkpoint、损失和种子之间固定。所有指标按用户等权平均。平局按物品编号打破，与标签无关；这里 AUC 不采用平局半分规则。
* BCE 使用所有训练评分；BPR 在有正负训练评分的用户中抽取已评分正负对。两种目标的采样含义不同，不能将实验解释为损失类别的普遍优劣。
* 相同矩阵分解架构，含用户/物品偏置；BPR 中与用户相同的偏置在分数差中抵消。按验证 AUC 或 NDCG@10 各选择一个 checkpoint，仅随后比较测试结果。
* 保存逐用户每个 checkpoint 的分数与标签，可独立复算排序。用户 bootstrap 区间和训练种子标准差分开报告，不把相邻 checkpoint 当作独立重复实验。

## 正确解释结果

regret 一律是固定标签理想排序与当前指标的差。Precision/Recall@k 的理想值未必是 1；全列表与截断 NDCG 分开计算。每个列表的 m、n 可以不同，因此不能把单一列表常数直接作用于宏平均而不处理权重。

前缀变化 h 是两个端点间的净变化；记录的物品对修复/破坏也是端点顺序差，不是期间全部交换次数。有效迁移系数仅在所有前缀不退步且总变化为正时报告。净变化接近零时以正负贡献分析为主。

单正例列表的 AUC 与 NDCG 不会发生方向冲突；多正例列表、单正例列表和聚合变化应区分。代码主动检查这一点。恒等式重构只验证实现与机制，**不是预测下一窗口的实验**；本项目不把未来 h 用作预测输入。

## 建议论文呈现

正文保留三组证据：紧常数/尺度对照、独立与耦合优化、真实训练冲突及位置贡献。完整枚举表、轨迹、切分协议和不确定性放附录。若真实训练未出现预想冲突或验证指标选择没有收益，应如实报告，而不筛选随机种子。

CPU 即可运行。完整训练时间取决于硬件与 checkpoint 数量，应以 `runs.csv` 中实测秒数估算；无需复现十亿候选的工业系统。本项目检验固定评估环境中的理论机制，不验证离线指标对线上商业收益的因果保证。
